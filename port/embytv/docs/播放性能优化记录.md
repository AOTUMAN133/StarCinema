# 滴滴TV 播放性能优化记录（2026-08-27）

> 调研：3 个并行子代理调研 GitHub（mpv-android / mpv / media3 1.10.1 / findroid / mpvKt / Jellyfin），全部带一手证据。
> 版本：v1.3.7（versionCode 227）

## 一、设备自适应分级（新增 DeviceTier.kt）

根据 **内存 / CPU 核数 / ABI** 综合评分判定高端/低端设备，MPV 内核参数据此自动选择：

| 依据 | 计分 |
|------|------|
| 总内存 ≥6GB / ≥4GB / ≥2GB | +3 / +2 / +1 |
| CPU 核数 ≥8 / ≥4 / ≥2 | +3 / +2 / +1 |
| 非 32 位 ABI (arm64/x86_64) | +2 |

- `score ≥ 5` → 高端设备
- 低端盒子（小米盒子 5 等 32 位、小内存）自动走低端路径
- 日志：`MPV device tier: high-end/low-end (mem=..GB cores=N abi=.. score=N)`

## 二、MPV 内核改动

### 设备自适应
| 参数 | 高端 | 低端 | 依据 |
|------|------|------|------|
| `vo` | `gpu-next` | `gpu` | 官方默认 gpu；gpu-next 有撕裂(#1289)/掉帧(#1227) |
| `hwdec` | `mediacodec`(单值) | `mediacodec,mediacodec-copy`(回退链) | 低端 surface 失败自动降 copy |

### 零风险优化（全设备）
| 参数 | 之前 | 现在 | 依据 |
|------|------|------|------|
| `stream-buffer-size` | 未设(默认128KB) | `4M` | mpv 手册：mp4 小 seek 性能差 |
| `cache-pause-wait` | 10 | `0.5` | rebuffer 恢复快一半 |
| `network-timeout` | 30 | `20` | 默认 60s 卡死连接拖死起播 |
| `vd-lavc-film-grain` | 未设 | `cpu` | 规避 mpv #14651 AV1 亮度翻转 |

## 三、EXO 内核改动

| 参数 | 之前 | 现在 | 依据 |
|------|------|------|------|
| `prioritizeTimeOverSizeThresholds` | false | **true** | 默认 false，seek 后更快起播 |
| `connectTimeoutMs` | 默认 8s | **3s** | 局域网连接失败快速暴露 |
| `readTimeoutMs` | 默认 8s | 8s(显式) | 保持 |
| bandwidthMeter 初始估计 | 默认 1Mbps | **15Mbps** | TV 局域网首帧直接高清 |

## 四、无需改的（已验证正确）
- EXO `bufferForPlayback=1s`（已优于 Media3 网络默认 50s）
- mpv `profile=fast`、`ao=audiotrack,opensles`（避开 aaudio #1283）、`vd-lavc-threads=0`
- 缓存 256MB 可配 + cache-secs=300 + cache-pause=yes

## 五、遗留/权衡
- **mpv #1127**（HEVC 硬解+切字幕冻结，open）：cache-pause 无法根治，仅缓解。根治需换新版 mpv 内核
- **媒体预取**（Media3 `PlayerId.PRELOAD`，进页秒开）：最高价值但工作量大，未做，列入后续
- `vd-queue-enable=yes`：手册称平滑播放，需设备 A/B 验证，未启用
